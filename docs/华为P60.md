# 华为 P60 真机调试指南（ShowLocation 首期主测机）

> 版本：v1.1 ｜ 更新日期：2026-09-20
> 机型系统：HarmonyOS 3.1 / 4.x（双框架，兼容 Android APK）
> 适用版本：本工程 Android 实现（含模拟位置 / 反推校准 / AL 探针）

---

## 1. 为什么用 P60 当测试机

- P60 是鸿蒙「双框架」机型，**可直接安装运行 Flutter 打出的 Android APK**，无需任何鸿蒙专属改造。
- 它覆盖了「鸿蒙兼容层 + 高德 Android SDK + 原生前台服务保活」这一纯 Android 机测不到的组合。
- 本项目最吃系统策略的两点 —— **前台服务不被冻结**、**Test Provider 生效** —— 在华为 ROM 上最容易出问题，
  因此 P60 是必须覆盖的机型。

> 注意：P60 验证的是「鸿蒙兼容层表现」，**不能替代原生 Android 机**（尤其是 Android 13/14/15 的权限弹窗与后台限制差异）。

---

## 2. 开启开发者选项与 USB 调试

1. `设置 → 关于手机 → 版本号`，连续点击 **7 次**，开启开发者模式。
2. `设置 → 系统与更新 → 开发人员选项`，打开 **USB 调试**。
3. 连接数据线，手机端弹「是否允许 USB 调试」→ 允许（建议勾选「始终允许」）。

## 3. **选择模拟位置应用（本项目必做）**

模拟位置功能的前提条件，P60 上路径：

```
设置 → 系统和更新 → 开发人员选项 → 选择模拟位置应用 → 选中 "showlocation"
```

未选中时 APP 会跳到该设置页并提示；选好后返回 APP 再点「应用到系统」。
（部分 EMUI / HarmonyOS 版本该项叫「允许模拟位置」或位于「更多设置」中。）

## 4. Windows 驱动（常见卡点）

- `adb devices` 认不到设备时，安装 **华为手机助手（HiSuite）** 自带驱动即可识别。
- 官网入口：`https://consumer.huawei.com/cn/support/hisuite/`（安装后首次连接按提示授权 HDB 连接）。
- 确认：`adb devices` 中该设备状态为 `device`。

> 只想要驱动：装完 HiSuite 后可在「设置 → 应用」中关闭其自启，驱动仍保留生效。

## 5. 允许安装未知来源 APK

`设置 → 安全 → 更多安全设置`，对用于安装的应用（文件管理器 / 浏览器）开启 **安装未知应用**，
否则鸿蒙纯净模式会拦截 APK 安装。

## 6. 安装与调试命令

```bash
# 构建（必须带 Key 注入参数，否则地图空白）
flutter build apk --debug --dart-define-from-file=keys/dart_define.json

# 安装（flutter install 默认找 release 包会报错，直接用 adb 装 debug 包）
adb install -r build/app/outputs/flutter-apk/app-debug.apk

# 实时日志（高德 / 定位 / 模拟 / 崩溃）
adb logcat | grep -i -E "amap|location|flutter|mock|AndroidRuntime"
```

APP 侧关键日志前缀（`debugPrint`）：

| 前缀 | 含义 |
|------|------|
| `[AMap] onLocationChanged:` | 高德 SDK 回调定位（含是否处于 mock 期间） |
| `[AMap] moveCamera:` / `readLatestLocation:` | 相机移动 / 读取最新回调 |
| `[AMap] regeo` / `inputtips` | 逆地理编码 / 联想搜索的 HTTP 结果 |
| `[Run] _applyLocation:` / `_applyBookmarkLocation:` | 模拟启动流程 |

## 7. 防冻结设置（保活必做）

华为「应用启动管理」默认自动管理，会冻结后台服务，导致 mock 中断：

```
设置 → 应用和服务 → 应用启动管理 → 找到 showlocation → 关闭"自动管理"
   → 勾选「允许自启动」「允许关联启动」「允许后台活动」
电池 → 更多电池设置 → 关闭「智能省电」或把本应用排除
```

本工程已做：`FOREGROUND_SERVICE_TYPE_LOCATION` 前台服务 + `PARTIAL_WAKE_LOCK`（tag `showlocation:mock_location`）+ 常驻通知。

## 8. 验证重点（对照 docs/requirements.md）

| 项 | 期望 |
|----|------|
| 定位权限弹窗 | 兼容层下能正常弹出并授权（选择「精确位置」） |
| 冷启动定位 | 5s 内出绿车标，地图跳到当前位置；超时有明确排查提示 |
| 地图渲染 | 拖动 / 缩放 / 旋转流畅，无黑屏错位（高德 Android SDK 在兼容层运行） |
| 选点与搜索 | 点选气泡、逆地理地址正常；搜索联想可用 |
| 收藏 | 保存 / 历史 / always（冷启动自动应用）正常 |
| **模拟位置** | 选点 → 应用到系统 → 通知栏出现「模拟位置运行中」；第三方地图 APP 显示注入位置 |
| **AL 探针 / 反推校准** | 紫 pin 出现，状态对话框「位置校准」偏差刷新；偏差 > 50m 时能观察到 1/4 → 2/4 轮次推进与最终收敛值 |
| **后台保活** | 切后台 / 熄屏 2 分钟后 mock 仍持续（`adb shell dumpsys location` 可辅助确认） |
| 停止模拟 | 移除 Test Provider，第三方 APP 恢复真实定位 |

## 9. 注意事项

- P60 验证的是「鸿蒙兼容层表现」，**不能替代原生 Android 机**对 Android 13/14/15 原生行为的验证；
  建议另备一台原生 Android 机互补（见 [`../supported_devices.md`](../supported_devices.md) 第 4 节）。
- 若未来走 **HarmonyOS NEXT（纯鸿蒙）**，本指南不适用：需 Flutter 鸿蒙分支 + 高德鸿蒙 SDK，
  且原生 mock 通道（`show_location/mock`）需要鸿蒙侧重新实现。
- **反 Mock 属系统级限制**：即使一切都配置正确，高德等 APP 仍可能识别 `isFromMockProvider` 并降权，
  这属于预期行为，不是本工程 Bug（详见 [`../lib/mock_location/mock_location_zh.md`](../lib/mock_location/mock_location_zh.md)）。

## 10. 设备号获取 + 安装命令速查（含 Key 参数）

### 10.1 获取手机设备号

```bash
flutter devices        # 推荐：输出「型号 (mobile) • 设备号 • 架构 • 系统」
# 示例：LNA AL00 (mobile) • YPL0223718053917 • android-arm64 • Android 12 (API 31)

adb devices           # 或：只列序列号 + 连接状态（需要设备已授权 USB 调试）
```

`flutter devices` 输出中用 `•` 分隔的**第二项**（如 `YPL0223718053917`）就是设备号，`-d` 用它指定目标设备。

### 10.2 运行（编译 + 安装 + 启动 + 看日志，一条命令）

```bash
flutter run -d <设备号> --dart-define-from-file=keys/dart_define.json
# 例：flutter run -d YPL0223718053917 --dart-define-from-file=keys/dart_define.json
```

> 只连一台手机时可省略 `-d <设备号>`；同时连着多目标（桌面 / 浏览器）时必须指定，否则可能装到错误目标。

### 10.3 构建 + 安装（独立使用，装完即用）

```bash
# 1) 构建（必须带 Key 注入参数）
flutter build apk --debug --dart-define-from-file=keys/dart_define.json

# 2) 安装
adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

### 10.4 参数说明

| 参数 | 作用 | 是否必须 |
|------|------|----------|
| `-d <设备号>` | 指定安装 / 运行目标设备（多设备时） | 单设备可省略 |
| `--dart-define-from-file=keys/dart_define.json` | 构建期注入高德 Key（源码已无明文 Key） | **必须**，否则地图空白 |
| `-r`（`adb install`） | 覆盖安装旧版本 | 建议带上 |

> 注意：`flutter install` 默认找 `app-release.apk`，会报 `does not exist`；装 debug 包请用 `adb install` 或 `flutter run`。
